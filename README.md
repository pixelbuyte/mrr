> **One file. Every AI tool's rules. Always in sync.**

## Why this exists

Every AI coding tool wants its own rules file. Claude Code reads `CLAUDE.md`.
Cursor reads `.cursorrules` (and now `.cursor/rules/main.md`). Copilot wants
`.github/copilot-instructions.md`. Gemini wants `GEMINI.md`. Windsurf, Cline,
and Aider all have their own formats too. If your team uses more than one,
you end up copy-pasting the same conventions into 5–7 different files.

Then they drift. Someone updates `CLAUDE.md` because that's the agent they
used today, ships the PR, and now Cursor and Copilot are giving the rest of
the team different advice on the same codebase. The whole point of agent
rules — consistent guardrails across every contributor — quietly breaks.

`rulesync` fixes this by making one file, `AGENTS.md`, the single source of
truth. A CLI command (and a GitHub Action) generates every other tool's
config from it. Edit one place; every agent stays in sync.

## Quick install

```bash
npx rulesync init
```

That scaffolds `AGENTS.md` and `rulesync.config.js`. If you already have a
`CLAUDE.md` (or any other supported file), it will use that as the seed.

## Usage

### Init from scratch

```bash
npx rulesync init
```

Creates `AGENTS.md` (a starter template, or seeded from your existing rule
files) and a default `rulesync.config.js` with all adapters enabled.

### Sync every tool

```bash
npx rulesync sync
```

Regenerates `CLAUDE.md`, `.cursorrules`, `.github/copilot-instructions.md`,
and every other enabled adapter from `AGENTS.md`. Each file is logged as it's
written. Files over ~2000 tokens get a yellow warning.

### Check for drift in CI

```bash
npx rulesync check
```

Reads `AGENTS.md`, regenerates the expected output in memory, and diffs
against what's on disk. Exits `1` if anything's out of sync — perfect for a
CI guard so reviewers never have to think about it.

### Use as a GitHub Action

```yaml
# .github/workflows/rulesync.yml
name: rulesync
on:
  pull_request:
  push:
    branches: [main]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pixelbuyte/mrr@v0.1.0
        with:
          mode: check
```

## Configuration

Drop a `rulesync.config.js` at the root of your repo to customize behavior:

```js
/** @type {import('rulesync').RulesyncConfig} */
module.exports = {
  // Source-of-truth markdown file (default: 'AGENTS.md')
  source: 'AGENTS.md',

  // Toggle individual adapters on or off
  adapters: {
    claude: true,
    cursor: true,
    copilot: true,
    gemini: true,
    windsurf: true,
    cline: true,
    aider: false, // opt out — Aider users often hand-tune their YAML
  },

  // Wrap each tool's output with a header or footer (optional)
  overrides: {
    claude: {
      header: '<!-- Auto-generated by rulesync. Edit AGENTS.md to make changes. -->\n',
    },
    cursor: {
      footer: '\n# Synced by rulesync',
    },
  },
};
```

## GitHub Action

### Mode 1: check on every PR (recommended)

Fails CI if anyone forgets to run `rulesync sync` after editing `AGENTS.md`.

```yaml
name: rulesync
on: [pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pixelbuyte/mrr@v0.1.0
        with:
          mode: check
```

### Mode 2: auto-sync on push to main

Generates the rule files for you and commits them back with `[skip ci]`.

```yaml
name: rulesync-auto
on:
  push:
    branches: [main]
permissions:
  contents: write
jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
      - uses: pixelbuyte/mrr@v0.1.0
        with:
          mode: sync
      - run: git push
```

## Contributing

PRs welcome — adding a new adapter is genuinely <10 lines:

1. Create `src/adapters/<tool>.ts` exporting an `Adapter`:
   ```ts
   import type { Adapter } from './index';
   export const myToolAdapter: Adapter = {
     name: 'mytool',
     outputPath: '.mytoolrules',
     render: (source) => source,
   };
   ```
2. Register it in `src/adapters/index.ts` and add the name to `AdapterName`
   in `src/config.ts`.
3. Add it to the supported tools table above.

That's it — `sync` and `check` automatically pick it up.
